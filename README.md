# Remap

`remap` provides compile-time checked enum and object mapping for Kotlin/JVM. It
maps enum constants by name and generates constructor calls without reflection.

The library targets JVM 17 and Kotlin 2.3.20. It has no Micronaut runtime
dependency and can be used in Micronaut 4 applications.

## Features

- Kotlin enum mapping with FIR validation
- Kotlin object mapping generated by an IR compiler plugin
- Recursive mapping for nested classes, enums, collections, and maps
- Explicit property and enum overrides
- Compile-time diagnostics with nested property paths

## Installation

Apply the Gradle plugin. It enables the compiler plugin and adds the runtime API
to each Kotlin compilation:

```kotlin
plugins {
    kotlin("jvm") version "2.3.20"
    id("me.flegr.remap") version "0.1.0"
}
```

Compiler plugin APIs are tied to the Kotlin compiler version. This release
requires Kotlin 2.3.20.

## Enum Mapping

Use the reified Kotlin extension:

```kotlin
val explicit = domainStatus.mapTo<ApiStatus>()
val inferred: ApiStatus = domainStatus.mapTo()
```

The destination may contain additional constants, but it must contain every
source constant. The compiler checks the complete enum, not only the value used
at a call site.

Use typed rules when names differ or an existing value needs to be remapped:

```kotlin
val result: ApiStatus = domainStatus.mapTo {
    DomainStatus.LEGACY mapsTo ApiStatus.UNKNOWN
    DomainStatus.ACTIVE mapsTo ApiStatus.ENABLED
}
```

Rules run before same-name mapping. Calls with rules intentionally skip full-set
validation because the rules may handle otherwise missing constants. If the
current value has neither a rule nor a same-name destination constant,
`IllegalArgumentException` is thrown at runtime.

## Object Mapping

Kotlin objects map to destination constructor parameters with the same names:

```kotlin
data class DomainProfile(val name: String, val age: Int)
data class ApiProfile(val name: String, val age: Int)

val result: ApiProfile = DomainProfile("Ada", 37).mapper()
```

The compiler generates a direct `ApiProfile(...)` constructor call. No
reflection or runtime property lookup is used.

Destination parameters may be absent from the source when they have defaults:

```kotlin
data class DomainSettings(val enabled: Boolean)
data class ApiSettings(
    val enabled: Boolean,
    val label: String = "default",
)

val result: ApiSettings = DomainSettings(true).mapper()
```

### Property Overrides

Use `from` to provide a value that cannot be mapped automatically:

```kotlin
data class DomainUser(
    val firstName: String,
    val lastName: String,
    val role: DomainRole,
)

data class ApiUser(
    val displayName: String,
    val role: ApiRole,
)

val result: ApiUser = domainUser.mapper {
    displayName from "${it.firstName} ${it.lastName}"
    role from it.role.mapTo<DomainRole, ApiRole> {
        DomainRole.LEGACY mapsTo ApiRole.UNKNOWN
    }
}
```

`it` is the source object. Each override must produce the destination property's
declared type.

### Nested Objects

Nested constructor properties map recursively:

```kotlin
data class DomainAddress(val city: String)
data class ApiAddress(val city: String)
data class DomainUser(val name: String, val address: DomainAddress)
data class ApiUser(val name: String, val address: ApiAddress)

val result: ApiUser = domainUser.mapper()
```

### Collections And Maps

Elements, map keys, and map values map recursively:

```kotlin
data class DomainItem(val name: String)
data class ApiItem(val name: String)

data class DomainCatalog(
    val featured: List<DomainItem>,
    val archived: Set<DomainItem>,
    val indexed: Map<String, DomainItem>,
)

data class ApiCatalog(
    val featured: List<ApiItem>,
    val archived: Set<ApiItem>,
    val indexed: Map<String, ApiItem>,
)

val result: ApiCatalog = domainCatalog.mapper()
```

Supported types are:

- `List` and `MutableList`
- `Set` and `MutableSet`
- `Collection` and `MutableCollection`
- `Iterable`
- `Map` and `MutableMap`

Mutable destination types produce mutable results. Conversions between the
supported iterable interfaces are allowed.

## Compile-Time Validation

The Kotlin compiler plugin validates `mapTo` and automatic object mappings.

Typical Kotlin diagnostics include:

```text
cannot map enum DomainStatus to ApiStatus: missing destination constants [DISABLED]
```

```text
cannot generate object mapping: child.status maps DomainStatus to ApiStatus,
missing [DISABLED]
```

Paths describe recursive traversal:

- `items[].status` identifies a collection element property.
- `items{key}` identifies a map key.
- `items{value}.status` identifies a map value property.

Missing and incompatible properties are also rejected:

```text
age has no source property
value has incompatible types kotlin.String and kotlin.Int
```

Add a destination default or a `from` override to resolve these errors.

## Limitations

### Arrays

JVM arrays and primitive arrays are not mapped recursively. Convert them in an
override:

```kotlin
val result: ApiArray = domainArray.mapper {
    items from it.items.map { item -> item.mapper() }.toTypedArray()
}
```

### IntelliJ

A dedicated IntelliJ plugin provides live Kotlin inspections without loading the
compiler plugin into IntelliJ's K2 analysis engine. It reports the same enum,
property, type, collection, and map validation failures while editing. Gradle
compilation remains responsible for validation and generated mapping code.

Build the plugin against IntelliJ IDEA 2026.2.1:

```shell
./gradlew -p intellij-plugin buildPlugin
```

To build against an existing installation instead of downloading the IDE:

```shell
./gradlew -p intellij-plugin buildPlugin \
    -PintellijPlatformPath=/path/to/idea
```

Install the ZIP from `intellij-plugin/build/distributions` through
**Settings > Plugins > Install Plugin from Disk**. The current plugin build is
compatible with IntelliJ branch `262` only.
